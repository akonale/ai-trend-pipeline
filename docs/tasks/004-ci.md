# 004: CI: GitHub Actions runs lint, types, tests on every PR

Status: built

## Goal

Add one GitHub Actions workflow that runs `just lint` (Ruff check, Ruff format check, Pyright strict) and `just test` (pytest, including the Temporal time-skipping test) on every pull request and on pushes to `main`. The PR for this task should show a green check.

## Acceptance criteria

- [ ] `.github/workflows/ci.yml` exists. It triggers on `pull_request` (all branches) and on `push` to `main`. It sets `permissions: contents: read` and uses a `concurrency` group keyed on the ref with `cancel-in-progress: true`. It has one job, `check`, on `ubuntu-latest` with `timeout-minutes: 15`.
- [ ] The job runs these steps in order: `actions/checkout@v4`. Then `astral-sh/setup-uv` (pinned major tag) with `enable-cache: true`, installing Python from `.python-version`. Then a pinned action that installs `just` (for example `extractions/setup-just@v2`). Then `uv sync --locked`, then `just lint`, then `just test`. CI calls the `just` recipes and does not copy their commands, so the justfile stays the single source of truth.
- [ ] The Temporal time-skipping test passes in CI. GitHub-hosted runners have network access, so the test-server binary is downloaded on first use. No extra caching step and no Docker or compose stack is needed. No secrets or environment variables are used by the workflow.
- [ ] `CLAUDE.md` drops "CI" from the "no speculative code" list, which becomes "(deploy, Bluesky specifics)". It also gets one line under "Task workflow" rules saying that a PR is ready to merge only when the CI check is green. `test_claude_md.py` keeps passing, and the file stays at 150 lines or fewer.
- [ ] `README.md` gets a short "CI" section (2 to 4 lines). It says that every PR and every push to `main` runs `just lint` and `just test` through `.github/workflows/ci.yml`.
- [ ] `just lint` and `just test` pass locally. After the scribe opens the PR, the `check` job on it is green. The scribe records the run URL or result in the handoff log.

## Tests to write

- `test_ci_workflow_triggers`: read `.github/workflows/ci.yml` as text and assert it contains `pull_request:` and `push:` with `main` under `branches`.
- `test_ci_workflow_runs_just_recipes`: assert the workflow text contains `uv sync --locked`, `just lint`, and `just test`, and that `just lint` appears before `just test`.
- `test_ci_workflow_has_no_secrets`: assert the workflow text does not contain `secrets.`.

(Plain text checks, so no YAML parser dependency is needed. Tests must be Pyright-strict clean.)

## Out of scope

- Branch protection or required-check settings on GitHub. Those are repo settings the human configures.
- Caching the Temporal test-server binary, or pre-downloading it. Add that only if CI turns out flaky or slow.
- A Python version matrix, other OSes, coverage reports, badges, or pre-commit hooks.
- Any deploy, release or scheduled workflow (task 015), and any Docker or compose step in CI.
- Changes to `justfile`, `pyproject.toml`, `uv.lock`, source code, `infra/`, `.claude/` or `docs/mvp-plan.md`.
